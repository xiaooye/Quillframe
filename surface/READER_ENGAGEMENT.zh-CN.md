# 读者吸引力 · 正文越过质量地板以后，继续判断它为什么值得读下去

<p><kbd>TIER C · 契约</kbd>&nbsp;&nbsp;<kbd>注意力</kbd>&nbsp;&nbsp;<kbd>回报</kbd>&nbsp;&nbsp;<kbd>继续阅读动力</kbd></p>

Surface Fundamentals 问的是：正文有没有结构破损、机械 AI 腔、薄弱因果、虚假抛光等问题。Reader Engagement 问的是另一件事：**读者为什么愿意继续、为什么觉得投入有回报、为什么在乎人物、为什么会更新自己对故事的理解，并真实感到局面正在变化？**

> **边界 ✦** Reader Engagement 是通用正向质量模型，不是一个总分，不要求全程最大张力，也不会覆盖类型、平台、项目与用户口味。Profile 改变的是权重和阈值，不是把某个维度删掉。

## 01 · 质量地板与正向质量不是一回事

一章可以通过全部 Surface hard rule，却仍然失败，因为它可能：

- 很安全，但像流程报告；
- 逻辑完整，却过于可预测；
- 所有配角都只有剧情功能；
- 情绪上没有生命；
- 每一步都正确，但几乎没有代价与选择；
- 结构完整，却没有继续阅读动力。

两层关系是：

```text
Surface Safety       = 最低实现地板
Reader Engagement    = 正向阅读价值模型
类型 / 平台          = 权重 + 阈值
项目 / 用户          = 进一步校准重点
```

通过 Reader Engagement 也不会获得 Canon authority，更不能替代 continuity 或 independent gate。

## 02 · RG-01 · ACTIVE READER QUESTION / 活跃读者问题

至少维持一个符合当前作品类型的近程活问题。

例如：

- 一个具体目标能不能完成？
- 另一个人会怎么选？
- 哪条隐藏信息会改变当前理解？
- 谁会付什么代价？
- 权限、地位、信任或接近资格会不会变化？
- 当可选方案越来越少，当前人物会怎么做？

问题应该变尖、分叉、解决，或者被更有后果的新问题替代。反复倒计时同一个威胁，并不算问题在演进。

安静 / 文学型作品可以使用更细微的 reader question；高抓力连载通常需要更强的近程牵引。

## 03 · RG-02 · PRESSURE LADDER / 压力阶梯

压力只有在改变可选方案时才真正有用。

一个有意义的 beat 可以：

- 去掉或削弱一个可行选项；
- 暴露或提高代价；
- 引入可信阻力；
- 揭出遗漏或错误；
- 迫使角色更早做决定；
- 解决一个压力，同时打开更严重的问题；
- 改变此前信息的意义；
- 改变关系许可或信任；
- 让“不行动”本身开始付代价。

不要为了“提高 stakes”随机加障碍。有效压力应来自人物、机构、资源、环境、先前选择、知识边界或已经埋下的状态。

## 04 · RG-03 · REWARD CADENCE / 回报节奏

读者需要对注意力获得回报，而不是只等一个很远的“最终正确答案”。

可能的回报包括：

- 能力兑现；
- 真正有用的信息 / reveal；
- 情感亲密；
- 社交逆转；
- 幽默；
- callback / recognition；
- 地位或权限提升；
- 一个令人满意的反驳被解决；
- 之前埋下的细节真正发挥作用；
- 可信但出人意料的人物行动；
- 当 profile 重视时，感官或修辞本身带来的阅读乐趣。

不存在统一“每章几次回报”的配额。真正要问的是：**在当前作品允许的注意力负债变得过大之前，读者有没有得到值得继续投入的东西？**

## 05 · RG-04 · FRICTION OVER PROCEDURE / 摩擦优先于流程

场景包含 routine process 时，应展开那些“流程真正变成故事”的地方：

- 人们不同意；
- 信息不完整；
- 一个错误被发现；
- 责任或风险转手；
- 时间 / 资源开始真正卡死；
- 必须在不完美选项中做决定；
- 关系状态改变了什么可以问、什么可以做；
- 专业能力暴露出意料之外的后果。

常规操作应压缩，除非“看专业流程本身”就是作品承诺的乐趣之一。

程序型小说也不是例外：流程必须提供能力展示、不确定性、发现、冲突、后果或领域乐趣。

## 06 · RG-05 · CHARACTER-OWNED ENERGY / 人物自有能量

重要人物应通过自己的东西给场景带来能量：

- 目标；
- 能力；
- 偏见；
- 幽默；
- 恐惧；
- 欲望；
- 社交策略；
- 信息；
- 主动性；
- 可信但不完全可预测的选择。

当除了主角之外所有人都只是剧情传送带，场景会迅速失去生命。

“Character-owned” 也意味着这种能量必须属于该人物真正拥有的知识、关系、社会位置和声线，而不是靠 narrator hype 代替。

## 07 · RG-06 · CHARACTER SURPRISE WITHIN CONSISTENCY / 一致性中的人物意外

让人物活起来的选择，经常需要同时满足两点：足够意外，让读者觉得这个人不是程序；又足够一致，让人回头一想觉得“确实会是他”。

机制例子，不是模板：

- 谨慎的人在风险变得非常具体时反而直接跳过礼节；
- 平时爱开玩笑的人在真正会出事时突然变得极其精确；
- 资历较浅的人抓到资深者的错误；
- 看起来像障碍的人因为自己的利益，反而给出最干净的解决办法。

不要随机制造怪癖。意外应该从目标、能力、经历、关系、信息、压力或此前未充分使用的人物侧面长出来。

## 08 · RG-07 · TONAL CONTRAST / TENSION WAVE / 调性对比与张力波形

持续最大张力最终会变平。低压 beat 只要有功能，反而能让后面的高压更有力，例如：

- 关系纹理；
- 幽默；
- aftermath；
- 信息；
- 假松一口气；
- setup；
- wonder；
- 安静但有效的道德 / 情绪确认。

Contrast 仍然必须做事。不要为了“波形好看”插 filler。

## 09 · RG-08 · CHARACTER-OWNED HUMOR / HUMANITY / 人物自有幽默与人味

需要幽默时，优先让它来自：

- 熟悉关系；
- 不兼容的目标；
- 地位错位；
- 专业 / 时代语言进入尴尬的人类情境；
- 真正带互动后果的误解；
- 自利；
- 压力下的黑色幽默；
- 之前一句很自信的话突然获得新意义。

最有效的幽默通常还会顺便暴露声线 / 关系、改变紧张或合作意愿、争取 / 浪费时间、埋信息，或加强后面的 reversal。

某个 profile 可以把 humor 设成 low / none。通用不变量只是：人味属于人物和处境，而不是可以随处粘贴的 narrator stand-up。

## 10 · RG-09 · OPENING ORIENTATION + GRIP / 开篇方向感与抓力

开头要给读者足够的 orientation，让他知道自己正在读什么，同时还要给出一个“为什么值得继续”的理由。

可能的抓力机制包括：

- 当前问题；
- 矛盾；
- desire + cost；
- 社交摩擦；
- deadline；
- 不寻常但具体的事实；
- 有辨识度的声线或幽默；
- 已经带电的关系状态；
- 来自真实信息边界的 mystery。

不要把“读者不知道发生什么”误当成“读者很好奇”。

## 11 · RG-10 · FORWARD-PULL ENDING / 前推型结尾

场景 / 章节结尾通常应该留下**已经改变的状态 + 一个让脑子继续往下走的理由**，具体形式取决于作品。

有效机制包括：

- 不可逆后果；
- 一个具体、未解决的近程问题；
- 已埋问题重新出现；
- recontextualization；
- 新的人 / 消息 / 物件进入；
- 下一状态的声音 / 感官侵入；
- earned callback；
- 已经做出的选择，但代价延后兑现；
- 关系权限或义务改变了下一步。

拒绝抽象 narrator advertisement。也不要求每章都 twist。

## 12 · RG-11 · INFORMATION VALUE / 信息价值

信息在到达时真正改变以下之一，才值得占据注意力：

- 解释；
- 选择；
- 预期；
- 情绪意义；
- 关系位置；
- 风险判断；
- 读者对“现在还有哪些可能”的模型。

避免只是填数据库字段的 exposition、为了 cheap mystery 故意拖普通信息，以及完全不理会当前行动节奏的定时 reveal。

好信息会改变读者模型，或者直接改变人物下一步。

## 13 · RG-12 · CAUSAL MOMENTUM / 因果动量

强场景让重要 beat 真正制造下一个重要 beat。

```text
原因
→ 反应
→ 状态改变
→ 新决定 / 新问题
```

纯时间顺序不是 momentum。“然后发生这个，然后又发生那个”可以非常清楚，却仍然毫无推进感。

## 14 · RG-13 · RELATIONAL MOVEMENT / 关系运动

重要互动经常应留下某种痕迹：

- 信任变化；
- 权限变化；
- 新义务出现；
- 吸引 / 排斥改变；
- 地位重新谈判；
- 私有信息变成共享信息；
- 一个人重新理解另一个人；
- 对未来的期待改变。

不是每次谈话都必须改变关系，但长篇里如果重大事件不断发生，而主要关系每章都自动 reset，小说会变得非常僵。

关系运动仍然服从 Canon / State 证据规则：Review Draft 可以写出 delta，当前权威关系状态仍要等 acceptance / settlement。

## 15 · RG-14 · SPECIFICITY OF STAKES / 代价具体化

压力越具体，越能真实改变人物选择。

优先使用可操作后果：

- 付不起 / 付得起的一笔钱；
- 会触发实际流程或社交后果的 deadline；
- 可能失去的权限 / access；
- 会直接拿掉行动选项的伤势；
- 可能消失的证据；
- 已经公开、不得不兑现的承诺；
- 会影响未来合作的关系代价。

“这一切都岌岌可危”通常不如一个人物现在必须绕着处理的具体限制有力。

## 16 · RG-15 · SAFE-BUT-FLAT / 安全但平

当文字技术上干净，却同时出现多项以下情况时，正向质量门槛应判失败：

- 章节按时间顺序汇报正确行动；
- 障碍第一次尝试就解决，没有 tradeoff；
- 对白主要负责传必要信息；
- 声线能区分，但没有真正人物感；
- 压力被宣布，却很少改变选择；
- procedure 比冲突 / 选择 / 后果占更多篇幅；
- 配角持续功能化；
- climax 只是因为 outline 说“该到了”；
- 状态改变了，但读者欲望没变；
- 几乎没有有效调性对比、人味或阶段回报。

修复必须**回上游**：Reader Pressure、Scene Simulation、Character Simulation 或 Story / Plan。不要靠随机 one-liner、更多碎句、形容词、假 twist 或 narrator hype 修“平”。

## 17 · Profile 权重

Profile 调整重点，不重新定义模型。

```yaml
reader_grip: low|medium|high|very_high
serial_forward_pull: low|medium|high
reward_density: low|medium|high
humor: none|low|medium|high
mystery: low|medium|high
relationship_motion: low|medium|high
procedural_pleasure: low|medium|high
rhetorical_pleasure: low|medium|high
contemplative_space: low|medium|high
```

例如：

- 高抓力商业连载会强权重 RG-01/02/03/04/10/12；
- cozy fiction 可以降低威胁压力，提高关系、回报、声线与舒适感维度；
- literary fiction 可以接受更慢的近程 propulsion，但要求更高的解释 / 情绪具体性；
- procedural fiction 只有在流程本身提供能力、未知、冲突、发现或领域乐趣时才值得展开。

Profile 改阈值，不会因为作品“安静”或“专业”就把某些质量维度彻底删除。

## 18 · Reader diagnostics 与 Reader Engagement contract 不是同一个东西

NovelForge 可以使用受限的 Reader Simulation Panel 收集诊断证据，例如 continue desire、pacing、confusion、emotional response、favorite / stumble beat、forward pull、character investment、reward、drop-off point。

这个面板只是本质量模型的**一个证据来源**，不是模型本身。

必须继续区分：

- 模拟读者 persona 描述阅读行为，而不是人口 stereotype；
- panel result 是诊断证据，不是 Canon；
- absolute score 不能单独决定 keep / discard；
- A/B 顺序交换可以暴露 position bias；
- 不同 persona 的分歧本身是有价值的证据，不应该一律平均掉；
- Reader Panel 不能自动满足 mandatory independent semantic gate。

详见 [质量演进](../docs/quality-evolution.zh-CN.md)。

## 19 · Engagement audit artifact

面向用户或机器的 audit 应记录结论和可观察证据，不记录 private reasoning。

```yaml
artifact_type: reader_engagement_audit
candidate_fingerprint:
active_reader_question:
question_evolution: []
pressure_ladder: []
reader_rewards: []
character_energy: []
tonal_contrast: []
information_value: []
causal_momentum:
relationship_movement: []
procedure_compression:
ending_forward_pull:
profile_weights:
flatness_risk:
result: pass|rewrite
```

输出应具体到能够把修复送回真正 owning mechanism。

## 20 · 失败路由

- active question / pressure 太弱 → Reader Pressure + Scene / Chapter planning；
- 没有有效回报 → 修 payoff / information / relationship / competence design；
- procedure 占满篇幅 → 压 routine，恢复 friction / choice / consequence；
- 人物能量缺失 → Character Simulation；
- 关系每章 reset → relationship state + scene design；
- surface-clean 但 flat → 上游 regeneration，不做 cosmetic polish；
- reader confusion 来自缺上下文 → 修 context / story information design；
- reader confusion 来自句子实现 → Surface layer；
- 不同 reader diagnostic 强烈冲突 → 查真实 tradeoff，不要盲目平均成一个数字。

## 21 · 不变量

1. Reader Engagement 是正向质量，不是缺陷黑名单。
2. Tension 不是唯一 engagement 机制。
3. Reward 不等于人物必须赢。
4. Forward pull 应来自故事状态改变，而不是 narrator advertisement。
5. 重要人物应贡献自己的能量。
6. Profile weighting 改阈值，不删除维度。
7. Reader diagnostics 是证据，不是 Canon，也不会自动变成独立审查。
8. SAFE-BUT-FLAT 必须回上游修。
