# 云端创作链路闭环

产品验收目标是在托管服务上完成整个网页流程：登录、创建项目、真实模型写作、独立审稿、显式接受、结算、下载出版物。Linux 是 Core 容器的实现依赖，不是读者或作者电脑的使用条件。本机安装 WSL、打开静态 Studio、使用模拟模型或成功导入容器模块，都不满足这项验收。

## 规格

沿用现有拓扑：Studio、同源 Cloudflare Worker BFF、WorkOS、WorkspaceCoordinator、SessionVault、加密 R2 bundle 和 Python Core 容器。保持 Host Bridge v11、SQLite 权威状态、CH001 范围、精确指纹、显式接受、独立审稿与单独结算的边界。

用户在云端创建项目，授权该新项目保存在自己的云端工作区；这不授权上传其他本地项目。容器重启后恢复当前原生快照属于运行时恢复，不是旧版项目迁移，也不是本地与云端同步功能。

只有容器停止后仍能恢复精确原生状态，托管写入才可报告为持久化成功。容器 `/tmp` 是执行存储，本身不构成持久化证据。模型凭据必须使用服务端秘密存储边界，托管 endpoint 校验必须约束 Core 实际使用的连接。浏览器输入不得提供可信工作区身份、Core proof、审稿人身份或发布回执。

验收测试可以由交互宿主调度真实 GPT 子代理。部署后的服务仍需要自己的鉴权模型执行与独立审稿调度器，不能依赖本次开发聊天持续在线。生成转发服务不构成独立审稿证据。

当前执行顺序是先完成本地生产验收，再做托管验收。本地流程必须使用真实 Core 存储、真实 GPT 生成、新的独立审稿调用、显式接受、结算及精确的出版产物。本地通过不代表下述云端持久化或部署门禁通过。

## 已复现的接线缺口

- C01 已修复 BFF 路径不一致、缺少 CSRF 和托管请求字节不符合规范化契约的问题。
- C01 同时修复了 JavaScript 整数键排序和特殊自有键保留，避免触发原型 setter；跨语言测试使用真实 Python 协议与 Cloud 解析器。
- C02 已把 Container 镜像配置从目录改为 Dockerfile，并使用固定版本 CLI 校验。
- C03 已增加显式鉴权的 Studio 初始化与唯一的资源/API 路由归属；会话生命周期及浏览器交付仍需验证。
- `project.create` 转发后没有建立工作区项目指针，下一次带项目范围的请求会被绑定校验拒绝。
- R2 upload/read 只校验或返回原生备份，没有恢复运行中 Core 的项目状态；当前容器目录不能证明重启持久化。
- 托管模型命令未接入 SessionVault lease 和实际目标绑定的 endpoint 校验；独立审稿缺少部署后的调度器。
- C06 已从 Core 恢复精确匹配的接受、结算回执，并通过稿件已存储的章节关联解析结算目标。有上限的收据窗口不能证明记录不存在，缺少章节关联时阻断结算。出版仍需可校验的下载产物，不能只有内部路径。

## 实施计划

1. 依据现有契约修复传输与部署配置，先复现失败再增加回归。不得自动绑定静态预览，也不得放松鉴权来让测试通过。
2. 补齐同源、已鉴权的 Studio 初始化与明确的资源/API 路由。分别验证登录、过期、CSRF、退出和未绑定的静态构建。
3. 定义并实现原子的工作区项目创建、原生快照持久化与恢复、写入确认。在使用真实稿件前，验证并发、上传失败、确认丢失、重启和删除。
4. 将模型凭据和 endpoint 校验接到真实 Core 执行器。增加服务端负责的独立审稿调度，使用冻结 packet 与真实调用身份。
5. 从 Core 恢复接受/结算状态，仅对精确校验过的产物提供出版下载。
6. 使用新登录会话、真实生成和独立审稿完成托管网页链路。重启容器后重新打开项目，核实项目状态、已接受正文、结算与下载字节仍与回执一致。

## 验证与回退

使用现有 Studio、Cloud、Python Core、持久化和出版测试。在容器实际文件系统上，以容器的非 root 用户执行 Linux 存储测试；不得替换锁、安全文件操作或用户身份来取得通过结果。真实托管会话、重启、模型、审稿、接受、结算和产物证据须与测试夹具分开记录。

传输/配置修改须与其调用端一起回退。新增持久化生命周期在失败恢复验证前不对外发布；保留原有项目快照，恢复失败时不能改用临时状态冒充成功。
