# 中文网文叙事实现与读者校准

2026-08-28 · 主模式 `SYSTEM-IMPROVE` · 状态：实施中，质量改善尚未验证。

本次经用户授权，将[上一轮研究](../025-chinese-webnovel-production/prose-quality-research.zh-CN.md)落实到真正发送给模型的输入、审稿规则和评测。研究记录保留原貌；不导入外部技能代码或小说原文，不内置下游项目事实，不自动激活用户偏好。

## 范围与验收

1. 写作阶段区分事件因果约束与正文组织：根据已授权视角、人物应对方式、对白诉求和叙事详略呈现文本。不得设置统一事件数、动作数、句长、视角或爽点配额。
2. 阅读定位来自当前冻结的明确公开声明，使用封闭类型、来源和指纹。写作、压力、盲读与独立审稿各自获得权限允许的输入；不扫描任意计划字典来推断公开信息。没有定位时不得编造。
3. 真实 Reader 与独立审稿判准要求从正文识别阅读价值，允许拒绝连贯但平淡的逐项汇报。安静日常、克制叙述及专业过程均有通过可能；压力提案不等于已经兑现的回报。
4. 作者可以对已释放的未接受草稿明确请求修改。新修订绑定原候选、原始释放证据及作者修改回执；历史审稿与文本保持不变。不得将作者请求伪装成原模型拒绝，也不得绕过新稿的全部门禁。
5. 完整中文合成场景用于校准，至少覆盖两个题材及正反对照。预期标签只是评测设计假设，不是人类认可或市场留存证据。普通测试不调用模型。

## 评测与权限边界

读者校准走登记的 `reader.engagement_audit`。未获得真实前置资格的样本不能派发 `quality.production_review`；其规则校准复用合法盲评入口，并完整绑定登记判准、目的及输出结构快照，明确没有生产权限。真正的生产独立审稿只能在新候选取得资格后另行执行。

生成对照与审稿校准分别记录输入、模型、调用数、原始结果、顺序和版本。固定样本上的误放行与误拒绝不等于普适质量。不能把测试通过或模型自评代替作者阅读。

## 兼容与回滚

版本目标：`quality` 契约包 8、`production-loop` 契约包 6、`narrative-memory` 契约包 4、`quillframe_repair_policy_v3`；公开项目格式仍为原生 1.0。旧契约只用于核查不可变历史证据或明确隔离的基线评测，新生产任务必须采用当前登记契约。禁止把历史结果升级成新候选的审稿证据。

登记语义任务仍限单次模型请求、180 秒，token 硬上限与普通生产阶段统一为 64,000。原先 32,000 的上限可能因完整权威规则、项目计划、正文和宿主开销而拒绝一份完整自检结果。这次调整不删规则，也不增加宿主已授权的累计调用数。

读者预期的输出格式只提供冻结账本允许的操作：新增项使用 `open` 和版本零；更新必须对应输入中存活条目的准确 ID 与版本。不能在同一次观察中先新增、再兑现，也不能向空账本提交虚构历史条目的更新。较窄的结构化输出格式保留原登记契约与模型原始 JSON，包括合法的可选兑现期限；领域校验仍不可省略。完整的嵌套 `anyOf` 分支遵循[官方 Structured Outputs 子集](https://developers.openai.com/api/docs/guides/structured-outputs)，根节点仍是封闭对象，不支持的关键词、格式和超限输入继续拒绝。

Reader 的有效 `fail` 必须原样保留，同时在预算内完成连续性检查与候选自检，形成正式修订所需的诊断来源；不得因此进入独立审稿或释放。Reader 待处理、证据非法、连续性失败及来源缺失仍阻断流程。已停止运行的确认结果不可改写；代码改变后必须开新运行，不能抹掉原失败及其消耗。

人物行动输出中的 `character_id` 与 `active_agenda` 是既有的回显字段，必须绑定输入中冻结的准确字符串。这些值来自项目状态或前序 AI 阶段；Python 不制定人物目标，也不判断行动是否符合目标。目标只是本次调用的输入基线，不是永久 Canon。具体行动、策略、解释和证据选择仍由模型决定，包括犹豫或相冲突的冲动。收窄这两个字符串时必须保留原登记契约、原始响应和最终绑定校验；只使用已实际执行过的字符串枚举，不引入新的供应商输出格式能力。

回滚基线为 `54c64c0`。新运行冻结准确代码与输入，禁止运行中替换源；回滚代码也不改写既有回执、候选或计费记录。模型预算沿用宿主已有累计授权，不重置历史消耗。

## 非目标

本次不部署云端，不推送远端，不自动接受或结算作品，不发布后续章节，不承诺平台留存或特定作者风格。

## 运行接口与验证材料

作者入口的 `payload.reader_positioning` 接受封闭声明：`schema=quillframe_reader_positioning_v1`、`visibility=reader_eligible`，以及至少一项非空的 `genre_profile` 或 `platform_profile`。每项至多 160 个字符；只声明可向普通读者公开的定位。章节位置从冻结的阅读顺序产生，不能在这里覆盖。缺少公开定位不会触发从私有计划中猜测定位。

`candidate.revision.request` 保持原有授权与幂等规则，返回可供下一次显式 `author.run.start` 使用的 `next_action.payload.repair_source`。其中只有 `source_candidate_id`、`revision_request_id`、`expected_candidate_fingerprint` 三个引用。新修订核查原始释放、完整评审证据及父链，冻结安全的修改要求投影；完整授权回执不进入写作上下文。内部失败候选继续使用已有的三引用入口。

内部续修从已验证的上一轮目标包继承明确的作者修改要求。要求发生冲突时，后来的作者指示优先；语义冲突由 Editor 判断，Core 只保留准确的来源引用和先后顺序。当前计划重新冻结，不照抄旧目标包中的过时计划。这些修改要求及修订历史都不进入盲读或独立审稿输入。

`evals/chinese_reader_calibration.py` 只准备、登记和统计评测，不派发模型。`prepare_calibration` / `save_prepared` 分离盲包和隐藏标签；`capture_execution_identity` 绑定实际运行配置；`record_result` 保留精确结果；`summarize` / `compare_reports` 报告分歧。只有明确授权的外部执行器可以消耗模型调用。本地身份必须带实际 `host_run_id`，不能伪装成 GitHub 工作流。

用户在实施中另行提供故事大纲时，生产验证可以新建原生项目并执行 `DRAFT`。它不能冒用旧稿的修订关系或继承旧格式项目的状态；私有素材和来源记录仍留在下游项目。
