# 长正文生成的有界截止时间

2026-08-28 · 主模式：`SYSTEM-IMPROVE` · 实现检查点；生产释放尚未验证。

## 已观察到的失败

基于 `e191fd7` 的一次生产运行完成十八个模型阶段后，正文生成 worker 触及配置的 150 秒上限，未返回最终消息。relay 在 170 秒后返回 HTTP 504。Core 保留了失败结果，没有释放候选稿。这证明发生了传输超时，不代表文学审查拒稿，也不能证明延长等待就一定成功。

## 范围

让有界请求截止时间从 Agent job 经 Model Runtime 和本地 relay 传递到 CLI worker；为两个完整正文生成阶段显式配置较长时限。普通请求的默认值，以及调用次数、token、身份、权限、持久化和释放边界均保持。

Python 负责时间与身份检查。叙事选择、写作约束的适用性、质量判断和修订决策仍由 AI 负责。不得为了缩短请求而删减指令、必需证据、正文目标或审查标准。

## 契约

1. 可选 `AgentBudget.max_model_request_ms` 将显式单请求时限绑定到 job 指纹。未提供时，序列化与现有 180 秒默认行为不变。实际请求同时受这一时限和 job 剩余时间限制。错误类型、非正值及超过 600,000 毫秒的值必须拒绝。
2. 生产中只有 `event_first_raw_draft` 与 `surface_realization` 显式使用 600,000 毫秒的单请求时限和总时限；仍各允许一次模型请求，token 与工具边界不变。其余阶段保持原预算。
3. Model Runtime 接受最多 600 秒的有限正数请求时限，默认仍为 180 秒。HTTP 传输不重试。向字面回环地址或 `localhost` 发起 POST 时，携带由实际请求预算生成的 `X-Quillframe-Deadline-Unix-Ms`。传输入口冻结本地截止时间，派发前的线上截止时间只可缩短，防止墙钟回拨使 relay 获得超过调用方剩余预算的时间。HTTP 预算与外层 journal 的时间原点不同，后者仍是额外的接受门槛。不得把截止时间元数据加入模型消息、请求体语义或远端提供商请求头。
4. relay 启动时显式配置有限正数服务器上限，默认 170 秒，最高 590 秒。调用方截止时间只能缩短该上限，并预留十秒供调用方接收响应。没有这一请求头时，不能静默获得超过普通 170 秒默认值的额度。
5. 当前 relay packet 冻结创建时刻与绝对到期时刻。发布 packet 前，relay 只能按墙钟与单调时钟的剩余额度缩短时限和到期时刻。原创建时刻、调用方截止时间与服务器上限保持不变；时限不得超过初始上限，到期时刻必须等于原创建时刻加该时限。无法保留正数额度时直接拒绝，不能重置时间原点。CLI driver 从准入、准备、执行到发布始终使用这一导出的到期时刻；排队和 schema 准备不能重新计时。worker 默认仍为 150 秒，可显式提高至最多 570 秒，并保留五秒发布余量。进程内单调时钟同时限制已准入工作，防止墙钟回拨延长运行。
6. 截止时间证据与原始请求、调用记录一起保存。过期或非法请求不得启动 worker；迟到或不完整的输出不得作为成功结果提交。已启动或失败的尝试继续计费；不加入自动重试、历史结果替换或恢复捷径。

## 兼容性与回滚

本地 relay 与 CLI 证据升级到版本 2。新执行要求当前 packet；旧 packet 和回执仅作为不可变历史证据保留，不引入兼容适配器。原生项目契约仍为 1.0，语义 worker 契约与文学评价标准不变。

回滚基线为 `e191fd7`。替换源码前必须确认 executor 已停止；新运行必须准确绑定源码。回滚不得改写旧结果、时间戳、候选稿或累计消耗。增加单次等待时间不等于获得额外模型调用授权。

## 验收

测试覆盖普通 job 原指纹与默认值、显式预算指纹、非法值、剩余时间裁剪、模型消息不变、仅回环地址传播请求头、服务器与调用方及 worker 的截止时间关系、延迟准入和准备、单调时钟到期、到期后不派发、不发布迟到结果、不重试，以及失败结果保留。普通 CI 不执行模型。只有另行完成真实生产与独立审查，才能声称已释放正文。

## 不包含

不引入语义重试 API、异步任务架构、新提供商、降低推理强度、删减正文要求、自动接受、事实结算、云部署或远端 push。
