# Context & Memory

Persistent storage is not model context. Quillframe selects a sparse working set for the current semantic question, then verifies the mechanical boundaries of that exact selection.

<img src="assets/concepts/sparse-context-manifest.en.svg" alt="Sparse Context Manifest selecting a small task-relevant subset from a larger Project store" width="100%" />

## Sparse Context Manifest

A Context Manifest may name the current book/volume/unit/chapter/scene, active characters and relationships, directly relevant state, claims, dependencies, recent Accepted material, and only the benchmarks that bear on the current craft problem. It is a selection contract, not a dump of the whole Novel Bible or Corpus.

Semantic relevance belongs to the model when genuine interpretation is required. Deterministic context code validates exact refs, receiving stage, authority class, provenance, fingerprints, private/hidden restrictions, invalidation state, and hard budgets after selection.

## Authority protection

`locked` and `accepted` references remain protected. Editing a derived memory view does not overwrite protected Canon; it produces a proposal or another explicitly non-authoritative artifact. Future Plan outcomes cannot leak into current-state fields merely because they are nearby in storage.

## Perspective and knowledge

<img src="assets/concepts/research-corpus-canon.en.svg" alt="Research, Corpus, and Canon remain separate evidence and authority classes" width="100%" />

Research truth is not automatic Character Knowledge. A character may receive a fact only through the Project's knowledge/state model and the actual story events that authorize that knowledge. Corpus evidence likewise never becomes character memory by ingestion.

## Generation isolation

Regression bad examples and hidden expected labels remain outside the writer's first-pass context. Post-generation auditors may receive additional authoritative rule or regression material without retroactively contaminating the already-frozen candidate.

## Memory lifecycle

Derived memory can be ranked, pinned, invalidated, rebuilt, or edited within its permissions. None of those operations promotes memory to Canon. Session persistence also does not mean provider history should be reinjected wholesale on resume.
